# Shubi Shot Director v0.5.0

Shubi Shot Director v0.5.0 adds parallel scene workspaces for independent Codex conversations while preserving the structured-only, loopback-only graybox workflow.

## Highlights

### Parallel scene workspaces

- Separate Codex conversations receive separate workspaces by default.
- Each workspace owns an independent bridge, SceneSession, revision history, runtime directory, port, browser URL, and Shot Preview.
- Every later command in a conversation automatically returns to the same workspace.
- `stop` shuts down only the current workspace, leaving other conversations running.

### Automatic routing and recovery

- `workspace current` reports the current opaque route.
- `workspace list` reports generic workspace health without private thread identifiers or runtime paths.
- `workspace attach --id <workspace-id>` explicitly attaches the current conversation to an existing workspace without copying or mutating its scene.
- The first eligible conversation can retain an existing legacy scene; later conversations receive isolated workspace directories.

### Privacy and safety

- The wrapper derives opaque workspace IDs with a one-way hash.
- Raw thread IDs never enter runtime arguments, environment, scene files, logs, screenshots, or exports.
- Port allocation and routing metadata use contained paths and atomic writes.
- Workspace operations never create SceneSpec revisions.

## Contracts And Upgrade Notes

- The application and Skill version are 0.5.0.
- SceneSpec, ScenePatch, and IntentReport remain at schema version 4.
- The capability contract remains version 2.
- Workspace routing requires `workspaceRoutingVersion: 1` and the `bridge.thread-workspaces` feature.
- Bridge protocol version remains 1.
- Existing no-thread callers retain the legacy single-workspace behavior.
- The package remains private to npm.

## Scope

Parallel workspaces support independent local scenes in separate Codex conversations. Remote hosting, shared live editing, cross-machine synchronization, and general multi-user collaboration remain out of scope.

## Verification

Focused workspace identity, atomic allocation, wrapper routing, compatibility, bridge health, process-boundary, TypeScript, ESLint, production-build, and public-audit checks pass. Final two-browser, two-scene, and two-export acceptance is recorded before integration.

The integrated release gate also keeps real-process workspace tests in a disposable runtime root, so verification cannot claim, stop, or rewrite an existing user scene. Loopback health probes tolerate short local scheduling stalls without treating a running bridge as unavailable. The final main-branch gate passes 64 test files and 1,540 tests, followed by lint, production build, and a 207-file public audit with zero findings.
