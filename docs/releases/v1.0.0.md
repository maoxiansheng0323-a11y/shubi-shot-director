# Shubi Shot Director v1.0.0 candidate

This document records the in-review v1.0.0 implementation. It is a Draft PR candidate only: no `v1.0.0` tag or GitHub Release has been created.

## Defining capability

For the supported still-shot vocabulary, Host Codex now authors semantic intent rather than final low-level 3D values. A transient `ShotIntentPlan` separates hard constraints from weighted soft preferences. The model-free loopback runtime deterministically solves scene relationships, delegates body support and relaxed-limb goals to the existing StaticBlocking subsystem, searches and ranks camera candidates, and waits for browser render-space evidence. Only one renderer-verified accepted candidate enters the authoritative `SceneSession` as an ordinary `SceneSpec`.

The normal path no longer requires Host Codex or a non-DCC user to guess actor translations, bespoke joint quaternions, final camera positions, focal lengths, or camera quaternions for supported shots. Existing direct editor controls remain available as refinement, recovery, and expert override.

## Structured contracts

- `ShotIntentPlan` schema version 1 supports bounded spatial relationships, facing, surface placement, region containment, StaticBlocking goals, visibility/body-part requirements, framing, caption and side-UI safe areas, depth order, and camera clearance.
- Hard constraints eliminate candidates. Soft preferences rank camera height, view angle, screen placement, lens tendency, headroom, look room, environmental context, and face readability without fake precision.
- `ShotIntentPatch` supports semantic set/remove revisions against the exact transient solve ID and generation. It invalidates prior render evidence and never exposes arbitrary JSON-path mutation.
- The CLI adds `shot solve`, `shot revise`, `shot candidates`, and verified-only `shot accept`.

## Deterministic solving and verification

- The relationship solver operates over a narrow, deterministic still-scene domain and explicitly rejects contradictions or unavailable targets.
- StaticBlocking remains the actor-pose subsystem. A semantic candidate must receive `pass`, not `check`, from pose/contact diagnostics.
- The camera solver searches bounded angle, height, distance, focal-length, and optical-axis samples. It rejects composition errors, required safe-area overlap, containment violations, depth-order failures, and camera-clearance failures, then selects meaningfully different balanced, dramatic-low, and environmental candidates.
- The browser renders every candidate with Three.js entity and actor-part ID passes plus isolated silhouettes. The server evaluates visible pixel ratios, screen bounds, clipping, safe-area overlap, required body-part visibility, and depth ordering. Missing, failed, mismatched, or stale evidence blocks acceptance.

## Compatibility and persistence

- `SceneSpec` remains the only persistent scene authority. Candidate plans, solved alternatives, scores, and render verification are transient.
- SceneSpec, ScenePatch, and IntentReport remain schema version 6. Existing saved scenes and direct structured `scene create` / `patch apply` callers remain compatible.
- Capability contract version 2, bridge protocol 1, workspace routing 1, host semantic authority, structured-only input, model-free execution, forbidden credentials, and loopback-only networking remain unchanged.
- Acceptance performs one `SceneSession.replaceScene` revision and clears the transient solve. A changed scene or stale generation fails closed.

## Generic acceptance candidate

The public [`examples/semantic-shot-flagship.shot-submission.json`](../../examples/semantic-shot-flagship.shot-submission.json) scenario contains a generic actor with one absent arm chain, pelvis support on world ground, upper-back support from a low box, the remaining arm resting on ground, bent resting legs, full framing, a slightly low camera tendency, and off-center placement. No final joint or camera quaternion is present in its semantic plan.

The automated v1 corpus covers 20 representative generic success and explicit-failure tasks. The flagship black box deterministically returned three world-valid and browser-verified candidates, while a side-on upper-back contact remained rejected. The top-ranked candidate was accepted without manual pose or camera rescue as `scene_semantic_flagship_1` revision 1; pose diagnostics passed and the connected browser exported a 1920 x 1080 PNG with SHA-256 `781D0A004232121A5C03463C170B35CBEE99C4816A153F8EE576C87D5F1234E2`.

The final gate passed 107 regular test files with 2,044 tests, the separate workspace e2e file with 1 test, TypeScript, ESLint, the production build, and two 329-file public/generic audits with zero findings. Detailed browser, contact, composition, warning, and export evidence is recorded in [`docs/verification.md`](../verification.md#v100-semantic-shot-solver-gates).

## Unsupported boundaries

This remains bounded graybox still-shot previs. v1.0.0 does not add animation, keyframes, physics, ragdolls, navigation, motion planning, general full-body IK, a generic optimizer or DCC, arbitrary mesh editing, final image generation, production asset management, or project-specific actors and story logic. Render-space verification is deterministic renderer evidence, not general computer vision, and human visual taste remains outside machine acceptance.
