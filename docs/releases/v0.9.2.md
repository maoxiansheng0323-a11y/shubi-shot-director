# Shubi Shot Director v0.9.2

Shubi Shot Director v0.9.2 is a focused editor-view control maintenance
release. It keeps the directly manageable studio introduced in v0.9.0 while
making large-scene navigation match the intended modeling-style workflow.

## Corrected studio navigation

- Left-drag on empty studio space now pans the UI-only editor view.
- Right-drag on empty space, room geometry, or other non-editable scene
  geometry now orbits around the editor view's current observation center.
- The wheel continues to zoom the editor view.
- Direct left-drag on an editable actor, prop, or camera proxy still moves the
  entity and takes priority over editor-view panning.
- Dragging a green actor part temporarily owns the pointer, so joint adjustment
  no longer pans the editor view at the same time.
- A short right-click that moves no more than the shared 5 px threshold clears
  transient entity and actor-part selection. A right-drag beyond that threshold
  orbits without clearing the current selection, even if the pointer later
  returns near its starting point.

## Root cause and boundary

The editor's `OrbitControls` had retained its default left-rotate/right-pan
mapping, while three separate context-menu paths cleared selection before a
right-button gesture could be classified. v0.9.2 gives the controls an explicit
left-pan/right-rotate mapping and centralizes right-click classification at the
editor surface.

The studio editor view is not a scene camera. Its position, orbit target, and
pointer gesture state remain transient UI data: they do not enter `SceneSpec`,
create a revision, change `activeCameraId`, or alter any persistent shot camera.
Expanded Shot Preview retains its independent final-camera controls.

## Compatibility and scope

- Application version: 0.9.2.
- SceneSpec, ScenePatch, and IntentReport schema version: 6.
- Capability contract: 2; bridge protocol: 1; workspace routing: 1.
- Existing `actor.pose-joints`, actor height, limb-presence, Blueprint, direct
  entity drag, camera refinement, and export contracts remain available.
- No persistent schema, migration, or generated-schema change was made.
- This remains graybox camera previs. v0.9.2 does not add inverse kinematics,
  animation authoring, physics, arbitrary mesh editing, final artwork
  generation, or production asset management.

## Verification status

The repeatable gates and dated evidence are recorded in
[`docs/verification.md`](../verification.md#v092-editor-view-mouse-control-gates).
The final local `pnpm verify` gate passed 97 test files with 1,941 tests, the
separate workspace e2e test (1/1), TypeScript, ESLint, the production Vite
build, and a 292-file public audit with zero findings. The generic-output audit
also scanned 292 files with zero findings.

A browser check at 1280 x 720 confirmed a nonblank large studio and compact
Shot Preview, empty-space left-pan without a revision change, short right-click
selection clearing without a revision change, and a direct blocking-cube drag
that created exactly one revision in an isolated generic instance. Both pages
reported no console warnings or errors. The automation surface could not
inject a held right-button drag, so real right-drag orbit remains the one
explicit human acceptance check. Automated tests cover the mapping constant,
its OrbitControls prop wiring, the 5 px gesture boundary, return-to-origin
drags, and pointer input ownership; the browser confirmed mounted left-pan.
